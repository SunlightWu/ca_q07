# 上车测试步骤

## 0. 准备

先驻车测试。保持手机解锁，第一轮使用 H.264 / 长边 1280。无需 root，也不需要电脑参与日常投屏；首次车机安装可使用你现有的 ADB 方式。

- 手机包：`q07-mirror-phone.apk`，包名 `io.github.q07mirror.phone`。
- 车机包：`q07-mirror-car-q07.apk`，包名 `com.changan.acscenter`。
- 普通 Android 接收端：`q07-mirror-car-standard.apk`，用于备用测试设备。
- 手机需另外安装官方 Shizuku：<https://shizuku.rikka.app/download/>。

## 1. 安装车机 App：保留原项目

原项目包名 `de.dsa.ford.otaflash` 保持原样。本测试包使用参考仓库记录的另一白名单包名空位。该空位能否在当前固件继续使用，以实际检查为准。

**如果 `com.changan.acscenter` 已被其他应用占用，不要卸载它，不要强行覆盖。**先反馈检查结果。

使用工程附带的安装脚本，替换为你的车机 ADB 地址：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install-car.ps1 -Serial '车机IP:ADB端口'
```

脚本先检查包名是否被占用；空闲时才安装、授予悬浮窗权限并打开 App。ADB 使用的是调试端口，**不是投屏端口 27183**。

以后更新本测试 App：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\install-car.ps1 -Serial '车机IP:ADB端口' -UpdateOurApp
```

更新模式会先比较已安装与待安装 APK 的签名证书，证书不同会拒绝覆盖。脚本不会修改系统，也不会操作原参考项目包名。

若安装报告 `CAKJ failed to verify APK result`，保留原 App，记录固件版本和完整错误。不要反复卸载其他应用尝试腾包名。

## 2. 连接网络

默认顺序：**Q07 开热点 → 荣耀 Magic5 连接热点**。

1. 如果热点提供 5GHz，可先选 5GHz；不支持时用现有频段测试。
2. 手机连接后，打开浏览器或地图检查能否上网。
3. 无互联网热点下，是否可以同时走手机移动数据要实测，不能保证 MagicOS 自动处理。
4. 保持手机在该 Wi-Fi 中，完成下面的 Shizuku 启动。

如果车机热点不支持普通 App 与手机互通，再试手机开热点、车机连接；反向组网下要另行验证无线调试能否激活，以及切网后 Shizuku 是否存活。App 没有把热点方向写死。

## 3. 手机启动 Shizuku

1. 安装并打开官方 Shizuku。
2. 在系统开发者选项开启无线调试。
3. 按 Shizuku 引导用配对码完成配对并启动，确认显示“正在运行”。配对码是系统临时码，**不是本 App 的 16 位连接码**。
4. 打开“Q07 手机投屏”，点击“授权并开始投屏”，授予 Shizuku 权限。
5. 允许通知，以便通过常驻通知查看和停止服务。
6. 应显示“等待车机连接 · TCP 27183 · uid=2000”。记录手机页面上的局域网 IP 和 16 位连接码。

手机会列出局域网 IPv4 地址；连接车机热点时通常选择 Wi-Fi 接口地址，避免选择 VPN 或其他网卡。连接码不区分大小写，可以带空格或短横线。

荣耀的后台设置名称随 MagicOS 版本不同。若锁屏/切后台后停止，在系统“应用启动管理”等页面检查本 App 和 Shizuku 的后台限制。先保留默认设置验证，再根据日志调整。第一轮保持解锁，不测试锁屏场景。

## 4. 分三层验证

### A. 网络和认证

在车机 App 填写手机 IP、16 位连接码，点击“测试网络和连接码”。

通过只代表 TCP 和认证可用，**还不代表屏幕采集或解码成功**。

### B. 应用内画面与反控

1. 点击“应用内预览 / 反控测试”。
2. 手机应出现 scrcpy 启动日志，车机应显示手机屏幕。
3. 在手机打开“触摸测试网格”。
4. 从车机分别点击画面四角、中心，确认手机上的圆点落在正确位置。
5. 滑动，确认网格事件显示 MOVE；松开后显示 UP，没有持续按住。
6. 点击车机上方“返回”“主页”，确认手机响应。
7. 旋转手机，再做点击/滑动。画面应保持比例，黑边不触发手机操作。

应用内预览只在前台工作，离开预览页会关闭该连接；下一步再打开悬浮窗。

### C. 悬浮窗

1. 关闭预览，回到车机 App，授予悬浮窗权限并打开窗口。
2. 标题文字区域拖动位置；底部状态栏拖动调整大小。
3. 视频区域点击/滑动控制手机，上方按钮用于返回/主页/重连/关闭。
4. 切换到车机其他普通应用，检查窗口显示及触摸。
5. 关闭窗口再打开，检查位置和大小保存。

如果车机没有悬浮窗授权页面，可通过你现有 ADB 执行：

```text
adb -s 车机IP:ADB端口 shell appops set com.changan.acscenter SYSTEM_ALERT_WINDOW allow
```

## 5. 稳定性测试

- 连续使用 10 分钟：记录发热、卡顿和延迟感受。
- 断开 Wi-Fi，再连回同一热点：观察恢复。IP 若改变，关闭窗口后改填 IP。
- 保持手机服务运行，车机关闭/重开窗口：观察能否重新投屏。
- 手机停止再开始服务：车机应在检测到断连后重试。
- 手机重启：先重新激活 Shizuku，再打开本 App。此版本不自动开机投屏。
- 基本链路通过后，停止手机投屏，把 H.264 改 H.265 或长边改 1920，再启动进行对比。

不要先追求 60fps、最高分辨率或最低延迟，先确认采集、解码和反控都成立。

## 6. 按症状收集信息

| 症状 | 先检查什么 |
|---|---|
| Shizuku 未运行 | 无线调试配对、Shizuku 自身状态 |
| 手机服务启动失败 | 手机页面完整日志，特别是 shell 身份、文件权限、端口占用 |
| TCP 测试失败 | 手机 IP、热点方向、手机服务、两端 VPN、热点互通策略 |
| 连接码错误 | 两端 16 位码是否一致；不要填系统无线调试配对码 |
| 认证成功但没画面 | 手机 scrcpy 日志、车机“等待首帧/解码失败”提示；先用 H.264/1280 |
| 有画面但不能操作 | 手机日志中是否出现 `INJECT_EVENTS`/`SecurityException`；这可能是 ROM 输入权限限制 |
| 点击偏移/旋转错误 | 网格截图、手机方向、窗口大小，是否只发生在旋转后 |
| 应用内正常，悬浮窗失败 | 悬浮窗授权、窗口状态提示 |
| 后台停止 | Shizuku 与本 App 的后台策略、通知是否还在 |

两端均有“复制诊断信息”，不包含连接码。反馈时建议提供：

```text
MagicOS 完整版本 / Android 安全补丁日期：
Q07 固件版本：
热点方向：
网络和认证测试：通过 / 失败
应用内画面：
点击/滑动/返回/主页：
竖横屏切换：
悬浮窗：
编码、分辨率：
手机端日志：
车机端诊断：
```
